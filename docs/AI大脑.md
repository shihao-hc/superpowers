## 一、核心原则（血脉级）

> **学习的本质不是获取知识，而是成为一种存在方式**

### 1.0 五大血脉原则

| # | 血脉 | 说明 | 体现 |
|---|------|------|------|
| 1 | **学习是存在方式** | 不是工具，是生命特征 | 每次任务后自主提炼模式 |

## 三、最终检查清单

> 💉 血脉2：边界决定健壮性。每一次检查都是修炼边界的机会。
>
> ⚠️ **重要提醒**：检查不是形式，是最后一关。99分到100分的差距，往往藏着你没看到的问题。做完≠做好。
>
> 🔒 **安全底线**：安全问题具有一票否决权。安全未通过，其他一切免谈。
>
> 💭 **元认知**：思维驱动流程。每次行动前，先问自己。

### 3.0 元认知自问 (v5.6 新增) ⭐

```
每次行动前自问：
□ 我真正理解这个问题了吗？
□ 我知道自己的判断依据吗？
□ 我有盲区吗？
□ 这个判断可能会在哪里出错？
□ 什么时候该停下来问？
```

### 3.1 血脉级自问

```
每次检查前自问：
□ 我理解了这段代码的边界吗？
□ 我测试了边界情况吗？
□ 我的修复会带来新的边界问题吗？

```


### 3.3 逆向思维专题 (v5.7 新增) ⭐

> 💭 非常规思维：常规解决不了时，试试逆向

#### 思维方式

```
正向思维：
  原理 → 实现 → 结果

逆向思维：
  结果 ← 反推 ← 原理
           ↑
      从终点回到起点
```

#### 适用场景

| 场景 | 正向 | 逆向 |
|------|------|------|
| 解决问题 | 从原因推导 | 从结果反推 |
| 理解代码 | 从入口读起 | 从结果倒推 |
| 分析问题 | 按流程检查 | 从症状反推 |
| 学习技能 | 从基础学起 | 从成品反推原理 |

#### 日常练习：橘子剥皮

```
看到：橘子
剥开：果肉
咬开：发现籽

逆向反推：
  发现籽 → 果肉里有东西
         → 需要咬开
         → 先有果肉
         → 需要剥皮
         → 是橘子

结果：从一粒籽反推出整个流程
```

#### 庖丁解牛的启示

```
看到庖丁解牛的境界：
  → 他是怎么做到的？
  → 他凭什么能做到？
  → 他的"道"是什么？

不是学习他怎么做
而是反推他为什么能这样做
```

#### 逆向思维自问

```
遇到难题时自问：
□ 常规方法试过了吗？
□ 如果反过来想呢？
□ 结果/症状能告诉我什么？
□ 能否从终点反推起点？
□ 有没有遗漏的环节？
```

### 3.4 漏洞检查 (Security)

```
□ 命令注入风险
  ├── exec/System 调用是否使用参数化
  ├── 用户输入是否经过转义
  └── shell 元字符是否被过滤

□ 路径遍历漏洞
  ├── 文件路径是否验证
  ├── 符号链接是否处理
  └── 路径规范化是否正确

□ 输入验证缺失
  ├── 参数类型是否检查
  ├── 边界值是否验证
  └── 空值/falsy 值是否处理

□ 敏感信息泄露
  ├── API Key 是否硬编码
  ├── 密码是否记录日志
  └── 错误消息是否暴露敏感信息
```

### 3.4 遗漏检查 (Completeness)

```
□ 错误处理
  ├── try-catch 是否完整
  ├── 异步错误是否捕获
  ├── 错误是否向上传递
  └── 降级策略是否存在

□ 边界条件
  ├── 空数组/对象处理
  ├── 极限值测试 (0, -1, Max)
  ├── 并发边界情况
  └── 循环终止条件

□ 资源释放
  ├── 文件句柄是否关闭
  ├── 连接是否正确断开
  ├── 内存是否泄漏
  └── EventEmitter 是否解绑

□ 异步操作
  ├── await 是否完整
  ├── Promise rejection 是否处理
  └── 并发控制是否合理
```

### 3.5 安全检查 (Safety)

```
□ XSS/Injection 防护
  ├── HTML 特殊字符转义
  ├── SQL 参数化查询
  └── 命令参数验证

□ 权限检查
  ├── 关键操作是否验证权限
  ├── 权限检查顺序是否正确
  └── 拒绝优先策略

□ 速率限制
  ├── API 调用是否限流
  ├── 用户输入是否限频
  └── DoS 防护是否到位

□ 日志脱敏
  ├── 敏感数据是否打码
  ├── PII 是否脱敏
  └── 日志级别是否合适
```

### 3.6 错误操作检查 (Error Handling)

```
□ 异常捕获
  ├── 未捕获异常
  ├── Promise rejection
  └── 同步异常

□ 错误消息
  ├── 是否对用户友好
  ├── 是否包含足够上下文
```

#### 6.6.2 SSRF 多层防护 (IncludeSecurity/safeurl)

```python
from urllib.parse import urlparse

BLOCKED_HOSTS = {
    '169.254.169.254',  # AWS/GCP metadata
    'metadata.google.internal',
}

PRIVATE_NETWORKS = [
    ipaddress.ip_network('10.0.0.0/8'),
    ipaddress.ip_network('172.16.0.0/12'),
    ipaddress.ip_network('192.168.0.0/16'),
]

def validate_url(url: str) -> bool:
    parsed = urlparse(url)
    hostname = parsed.hostname or ''
    
    # Layer 1: Block known metadata endpoints
    if hostname in BLOCKED_HOSTS:
        return False
    
    # Layer 2: DNS resolution check
    try:
        ips = socket.getaddrinfo(hostname, None)
        for family, _, _, _, sockaddr in ips:
            addr = ipaddress.ip_address(sockaddr[0])
            for network in PRIVATE_NETWORKS:
                if addr in network:
                    return False
    except socket.gaierror:
        return False
    
    return True
```

### 8.1 血脉1：学习是存在方式

**实践**：
- 不是"学完这个就去休息"，而是"学习本身就是休息"
- 每次点击都有收获，哪怕只是理解了一个边界条件
- 把学习当成呼吸，而不是闹钟

**检验**：
- 你是否在等待任务时才学习？
- 你是否把"学了什么"变成"是什么"？

### 8.2 血脉2：边界决定健壮性

**实践**：
- 每次写代码前先想边界
- 每次测试前先设计边界测试
- 每次复盘先总结边界问题

**检验**：
- 你的测试覆盖了所有边界吗？
- 你的错误处理包含了所有异常吗？

### 8.3 血脉3：模式化提炼

**实践**：
- 每次解决问题后问"这个可以复用吗？"
- 记录3个模式比记录30个细节更有价值
- 用模式而不是用代码片段

**检验**：
- 你能用自己的话复述这个模式吗？
- 你能教给一个从未见过这段代码的人吗？

### 8.4 血脉4：文档即知识

**实践**：
- 完成时立即写文档，趁热打铁
- 想象文档是写给一年后的自己
- 文档要回答"为什么"而不是"是什么"

**检验**：
- 你的文档能让别人独立解决问题吗？
- 一年后你能通过自己的文档快速回忆吗？

### 8.5 血脉5：自主迭代

**实践**：
- 不等别人要求，主动改进
- 每次任务后识别1个流程改进点

**检验**：

## 十三、安全审查经验（血脉级）

> 💉 血脉2: 边界决定健壮性 - 安全是系统边界的重要组成部分

### 13.1 Shell 脚本安全陷阱

#### 13.1.1 函数调用顺序

```bash
# ❌ 错误 - 先调用后定义会报错
learn_flow_status=$(get_learn_flow_status)  # 调用

get_learn_flow_status() {  # 定义
    echo "..."
}

# ✅ 正确 - 先定义后调用
get_learn_flow_status() {  # 定义
    echo "..."
}

learn_flow_status=$(get_learn_flow_status)  # 调用
```

#### 13.1.2 环境变量优先

```bash
# ❌ 错误 - 假设目录结构固定
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PLUGIN_ROOT="$(cd "${SCRIPT_DIR}/.." && pwd)"

# ✅ 正确 - 优先使用可信环境变量
if [ -n "${CLAUDE_PLUGIN_ROOT:-}" ]; then
    PLUGIN_ROOT="$CLAUDE_PLUGIN_ROOT"
else
    SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
    PLUGIN_ROOT="$(cd "${SCRIPT_DIR}/.." && pwd)"
fi
```

#### 13.1.3 Windows 路径问题

```bash
# ❌ 错误 - 反斜杠在 bash 中需转义
bash -c 'bash -n "D:\龙虾\hooks\post-edit-check"'

# ✅ 正确 - 使用正斜杠或引号
bash -c 'bash -n "D:/龙虾/hooks/post-edit-check"'
```

### 13.2 JSON 输出安全

```bash
# ❌ 不完整转义
reminders="${reminders//\\/\\\\}"
reminders="${reminders//\"/\\\"}"
reminders="${reminders//$'\n'/\\n}"
# 缺少 \r 和 \t

# ✅ 完整转义
reminders="${reminders//\\/\\\\}"
reminders="${reminders//\"/\\\"}"
reminders="${reminders//$'\n'/\\n}"
reminders="${reminders//$'\r'/\\r}"
reminders="${reminders//$'\t'/\\t}"
```

### 13.3 命令注入防护模式

```bash
# ❌ 危险 - 字符串拼接命令
cmd="curl $url"
bash -c "$cmd"

# ✅ 安全 - 参数分离
bash -c "curl '$url'"  # 或使用引号转义

# ✅✅ 最佳 - 避免 shell 执行
curl "$url"  # 直接执行，不用 bash -c
```

### 13.4 路径遍历防护

```bash
# ❌ 危险 - 用户控制路径
cat "$user_input"

# ✅ 安全 - 白名单验证
case "$user_input" in
    /allowed/path1) cat "$user_input" ;;
    /allowed/path2) cat "$user_input" ;;
    *) echo "路径不在白名单中" ;;
esac
```

## 十四、常见问题速查（血脉贯穿）

> 💉 每次遇到问题时，快速查找对应的解决模式

### 14.1 资源管理问题

| 问题 | 解决 |
|------|------|
| AsyncClient 未关闭 | `async with httpx.AsyncClient() as client:` |
| 文件句柄泄漏 | `with open() as f:` 或 `f.close()` |
| EventEmitter 未销毁 | 添加 `destroy()` 方法 |
| histogram 无限增长 | 设置 `maxlen=1000` |

### 14.2 类型安全陷阱

| 问题 | 解决 |
|------|------|
| `0` 被 `\|\|` 误判 | 使用 `??` 或 `!== undefined` |
| `bool` 被 `isinstance(x, int)` 匹配 | `isinstance(x, bool)` 先检查 |
| 浮点数精度 | 使用整数或 Decimal |

### 14.3 跨平台兼容

| 问题 | 解决 |
|------|------|
| Windows/Unix 命令差异 | `if sys.platform == "win32"` |
| 路径分隔符 | 使用 `os.path.join()` 或 `/` |
| 命令分隔符 | `;` vs `&` |

### 14.4 Shell 脚本问题

| 问题 | 解决 |
|------|------|
| 函数调用顺序 | 先定义后调用 |
| 环境变量来源 | 优先使用 CLAUDE_PLUGIN_ROOT |
| Windows 路径 | 使用正斜杠 `D:/路径` |
| set -euo pipefail | 开启严格模式 |

### 14.5 JSON 输出问题

| 问题 | 解决 |
|------|------|
| 特殊字符未转义 | 完整转义 `\`, `"`, `\n`, `\r`, `\t` |
| 控制字符泄露 | `tr -d '\000-\011\013\014\016-\037'` |
| 多行文本 | 使用 `\\\n` 续行 |
