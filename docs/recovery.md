# 灾难恢复指南

## 概述

本文档描述系统的灾难恢复流程，确保在发生重大故障时能够快速恢复正常运行。

## 备份策略

### 定期备份

| 备份类型 | 频率 | 保留时间 | 存储位置 |
|---------|------|----------|----------|
| 代码备份 | 每次发布 | 30天 | 本地 + 云存储 |
| 数据库备份 | 每日 | 90天 | 云存储 |
| 配置备份 | 每周 | 90天 | 云存储 |

### 备份脚本

```bash
# 创建备份
node scripts/backup/backup.js create

# 列出备份
node scripts/backup/backup.js list

# 恢复备份
node scripts/backup/backup.js restore <manifest-file>
```

## 灾难场景

### 1. 服务器完全宕机

**恢复步骤：**

1. **评估损失**
   - 确定宕机原因
   - 评估数据损失范围
   - 确认备份可用性

2. **启动新服务器**
   - 使用基础镜像创建新服务器
   - 安装依赖：`npm install`
   - 恢复配置：复制 `.env` 文件

3. **恢复代码**
   ```bash
   # 从Git恢复
   git clone <repository>
   cd <project>
   
   # 恢复备份中的文件
   node scripts/backup/backup.js restore <backup-manifest>
   ```

4. **恢复数据**
   - 恢复数据库
   - 验证数据完整性
   - 启动服务

5. **验证**
   - 检查健康端点
   - 运行测试套件
   - 确认功能正常

### 2. 数据库损坏

**恢复步骤：**

1. **停止写入**
   - 暂停所有写入操作
   - 防止数据进一步损坏

2. **恢复数据**
   ```bash
   # 从最新备份恢复
   <database-restore-command> --backup=<latest-backup>
   ```

3. **验证数据**
   - 检查数据完整性
   - 验证关键表
   - 确认业务逻辑正常

### 3. 代码回滚

**Git回滚：**

```bash
# 查看提交历史
git log --oneline

# 回滚到指定版本
git revert <commit-hash>

# 或强制回滚（慎用）
git reset --hard <commit-hash>
git push --force
```
