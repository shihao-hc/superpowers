# 闲鱼网页版「可自动化程度」PoC 结果

> 日期：2026-10-16 ｜ 方法：真实浏览器（Playwright，有头/无头对比）实测，非推断
> 工具：`scripts/xianyu-poc.js`（登录复用本地 profile，只读页面结构，**不自动提交任何发布**）

## 【观察到的】（有实测证据）

| # | 结论 | 证据 |
|---|------|------|
| 1 | **无头浏览器被风控拦截** | 无头打开 `/publish` → 正文「非法访问，为了保障您的体验，请使用正常浏览器访问闲鱼」 |
| 2 | **有头浏览器能通过** | 有头打开同一页 → 正常渲染（"登录 / 订单 / 消息 / 立即登录"） |
| 3 | **登录后发布表单完整可用** | 扫码登录后 `/publish` 渲染出：宝贝图片\*、宝贝描述\*(0/1500)、价格\*、原价、发货设置(包邮/按距离/一口价/自提/无需邮寄)、宝贝所在地、`[发布]` 按钮 |
| 4 | **字段可定位** | 两个 `input[type=text]` 占位 `0.00`（价格、原价）+ 4 个 radio（发货设置） |
| 5 | **登录态可持久化** | 关闭后用同一 profile 新进程打开 → 仍是登录态（不必每次扫码） |
| 6 | 登录检测不能靠 URL 重定向 | `/publish` 未登录时**不跳转** `/login`，而是内联显示「立即登录」→ 首版检测误报，已修 |

## 【不知道的】（尚未验证）

- 图片上传（"添加首图"的文件 input）能否自动化
- "宝贝描述"是富文本编辑器还是 textarea（填充方式不同）
- 点`[发布]`后是否触发**滑块/风控**（真正的拦路虎）
- 发布成功后跳转、消息回复、擦亮等是否有网页版入口

## 结论

**网页版「发闲置」可访问、字段可定位 → 自动填表技术上可行**（有头模式 + 登录 profile）。
因此推荐**半自动方案**：

```
我（AI）：打开发布页 → 填好标题/描述/价格/发货设置 → 停在"发布"前
你（人）：看一眼 → 点[发布]（过可能出现的滑块）
```

**未采用全自动的原因**：① `[发布]` 的滑块/风控未验证，强过可能触发封控；② 平台 ToS 禁止脚本化操作，**封号是致命成本**；③ 半自动已拿到 90% 效率。

## 安全与风险（诚实）

- profile（含登录 Cookie）存 `data/xianyu-profile/`，**已 gitignore，绝不提交**；脚本不碰账号密码
- 平台 ToS 风险：频繁自动化操作可能触发风控/封号 → 半自动（人在场）显著降低
- 脚本**只 dump 页面结构，不点击发布**；是否扩展"填草稿"需用户授权
