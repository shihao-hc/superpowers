# 接单 SOP（从接单到交付）

> 目标：每一单都**快、准、不出纠纷**。纠纷和返工是这类单最大的利润黑洞。

## 0. 接单前必问三件事（问错 = 后面全白做）

| # | 问 | 为什么 |
|---|----|--------|
| 1 | 数据规模？（多少行/几个表） | 决定工作量和报价 |
| 2 | 原始格式？（截图看一眼前几行） | 决定要不要清洗、有没有编码坑 |
| 3 | 要什么结果？（要什么列、什么格式、什么时候要） | 需求不清 = 无限返工 |

**铁律：只接「有明确输入 + 明确输出」的单**。客户说「帮我处理好这些数据」但给不出处理逻辑 → 先逼他讲清楚，否则不接。

## 1. 拿样本

- **先要前 100 行**，不要一上来就要全量数据。
- 两个好处：保护客户隐私 + 避免被 10 万行卡住。样本能跑通，全量基本没问题。

## 2. 处理（AI 干活）

- 客户数据发我 → 我用 `scripts/data-report.js` 处理。
- 脱敏：涉及姓名/手机号/身份证/银行卡的，**先把敏感列替换成占位符**再处理。
- 常见需求直接套命令（见 README「交付引擎用法」）。

## 3. 自己先验证（绝不能省）

- 拿样本数据跑一遍，**确认结果正确**再交付。
- AI 公式/脚本会漏边界条件（空值、重复、异常格式），所以：
  - 小数据全量看；大数据先抽 100 行看；
  - 核对合计、去重数、空值处理是否符合预期。
- **绝不把未经自己验证的结果直接转发给客户。**

## 4. 交付（防纠纷三件套）

交付给客户三样：
1. **处理好的 Excel 源文件**
2. **一段简短说明**（做了什么、怎么用）
3. **一段 10 秒操作录屏**（客户照做）——**录屏是防纠纷神器**：客户说「复制进去报错」的投诉直接归零。

**修改原文件？不。** 引擎只读输入、另存输出，客户的原始文件一个字都不动。

## 5. 转月包（把散单变现金流）

交付后主动问一句：

> 「这个表是每周/每月都要做重复的吗？如果是，我可以帮你做成自动的，以后每月几秒钟出新表。」

签下月包 = 每月固定收入，且后续每单成本极低（Agent 跑 + 你审核）。

## 话术模板

**首次回复（客户发来需求）**
```
您好，我看下您的需求。先跟您确认三个问题：
① 大概多少行数据 / 几个表？
② 方便发前 100 行截图或样本吗？我看下格式。
③ 您想要的结果是什么样（要哪些统计、什么格式）？
确认清楚我给您报个价，合适就开工。
```

**报价**
```
您的需求我看懂了，属于【多表合并 + 分组汇总】，预计当天能交付。
报价 X 元，交付：处理好的 Excel + 操作说明。
这个价格包含【需求清单】；如果后面要加新的统计项，按新需求另算。
可以的话我这就开始。
```

**催样本 / 卡需求**
```
麻烦把样本（前 100 行）发我，我确认下格式再动手，避免做出来跟您要的不一样。
```

## 避坑清单（真实教训）

| 坑 | 做法 |
|----|------|
| 🔴 **直接转发 AI 结果** | 客户复制进去报错 → 投诉。**必须先自己验证 + 附录屏** |
| 🔴 **碰税务申报** | 需会计资格，**不做**。数据整理 ≠ 出税务结论，接单话术里就划清 |
| 🔴 **碰客户生产数据库** | 边界只到「Excel/CSV 文件」，不碰 ERP/CRM/生产库（写错赔不起） |
| ⚠️ **需求蔓延** | 开工前书面确认「包含哪些」，超出另报价 |
| ⚠️ **隐私** | 敏感字段脱敏后处理；与客户做简单保密约定 |
| ⚠️ **编码坑** | Excel 导出的 CSV 常是 GBK，需先转 UTF-8（引擎当前只吃 UTF-8） |
| ⚠️ **强反爬的采集单** | 打码/强验证码的爬虫单周期不可控，**新手先别接** |

## 这一单做完了要做什么（复盘 + 沉淀）

1. 把新遇到的**需求类型**记下来 → 判断要不要给引擎加能力（按真实订单长，不提前堆）
2. 把客户评价/交付文件截图存好 → 上架素材 + 好评
3. 稳的单做成**模板**，下次更快
